# NSQ Event Management System

A Microsoft Dynamics 365 and Power Platform-based Event Management System developed as a team mini-project.

## 1. Project Overview

The NSQ Event Management System aims to provide a centralized solution for managing event-related information and activities using Microsoft Dynamics 365 and the Power Platform.

The project focuses on configuring Dataverse tables, developing client-side validations, implementing server-side business logic through plugins, automating business processes using Power Automate, and deploying the solution across environments.

## 2. Project Objectives

- Design and configure Dataverse tables, columns, relationships, forms, and views.
- Implement client-side validations and business logic using JavaScript.
- Develop server-side business logic using C# plugins.
- Automate business processes using Power Automate cloud flows.
- Configure security roles and access permissions.
- Build and organize a model-driven application.
- Test functionality and handle relevant edge cases.
- Manage solution development, version control, and deployment.

## 4. Project Components

The project includes the following development areas:

- **Dataverse Configuration:** Tables, columns, relationships, forms, views, keys, business rules, and security.
- **JavaScript:** Form events, field validations, client-side logic, and user experience enhancements.
- **Plugins:** Server-side validations, business logic, and data operations.
- **Power Automate:** Automated workflows, notifications, and process automation.
- **Model-Driven App:** Application configuration, navigation, and user experience.
- **Solution Management:** Solution organization, version control, testing, and deployment.

## 6. Team Collaboration

This project is developed collaboratively by a team of four members.

Every team member is expected to contribute to:

- Dataverse and Power Platform configuration.
- JavaScript development.
- C# plugin development.
- Power Automate development.
- Solution management and deployment.

Work will be divided into individual tasks and features while ensuring that every member gets practical exposure to the required development areas.

## 7. Git Workflow

The repository follows a feature-branch-based workflow.

- `main` – Stable and reviewed project version.
- `feature/<feature-name>` – Development of a new feature or functionality.
- `bugfix/<issue-name>` – Fixes for identified issues.

All feature and bug-fix changes should be submitted through Pull Requests, reviewed, and merged into `main`.
